THE BOUNDARY

A draft is not a send.
A send is not a reply.

Each stage needs its own evidence. A second source for the same role adds context to one opportunity; it never becomes another application. Excluded employers are filtered before contact. This demo reads a static snapshot and cannot message anyone.

How this snapshot was built ↘

The public repository contains six synthetic source rows and a separate event table. A Python script loads them into an in-memory SQLite database. SQL uses ROW_NUMBER() OVER (PARTITION BY opportunity_id) to select one canonical record, then joins the latest evidence event to derive the displayed state and counts. The script refuses non-synthetic IDs, real-looking companies, URLs and email addresses. The browser reads only the generated JSON; it cannot access the production CRM.

Codex wrote the generator, SQL and interface. Ivan's portfolio claim is process design, AI direction and acceptance of the evidence boundaries, not independent SQL engineering.
