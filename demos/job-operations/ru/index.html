Для каждого этапа нужно своё подтверждение. Второй источник той же вакансии дополняет одну запись, а не создаёт новый отклик. Исключённые компании отсеиваются до контакта. Стенд читает статический набор и никому не пишет.

Как устроен стенд ↘

В открытом репозитории есть шесть вымышленных исходных записей и отдельная таблица событий. Python загружает их во временную базу SQLite. SQL использует ROW_NUMBER() OVER (PARTITION BY opportunity_id) для выбора одной записи на вакансию, затем соединяет её с последним подтверждённым событием и рассчитывает статусы и счётчики. Скрипт отклоняет идентификаторы без метки synthetic, похожие на реальные компании названия, URL и email. Браузер читает только готовый JSON и не имеет доступа к рабочей CRM.
