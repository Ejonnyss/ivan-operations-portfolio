03 / AI-ASSISTED OPERATIONS

Job & income operations

A private system that keeps discovery, application work and actual responses distinct.

Context and problem

A job search generates many leads, overlapping channels and dates. The operational risk is losing the reason for a decision, duplicating an application or treating a sent message as an employer response.

Workflow

Discovery → qualification → duplicate check → role-specific materials → recorded application → follow-up date → response analysis. The working records include a CRM and exclusions. The public case does not expose company names, contacts, correspondence or personal resume data.

Evidence boundary: the system tracks confirmed states separately. A prepared letter is not a sent application; a sent application is not a reply; a reply is not an interview or paid work.

Architecture and decisions

The current workflow is an agent operating with a preserved local CRM, blacklist, status log and human review points. It reads each opportunity, checks exclusions and channel history, drafts tailored materials and records only observed state transitions. This is an operations design and documentation case, not a released autonomous application platform.

AI role and human control

Codex can discover opportunities, normalize information, draft material and maintain records. The owner supplies career facts and approves the operating boundaries. No AI hiring decision is made. Claims in an application must be grounded in resume evidence.

Result and limits

The case demonstrates a guarded, repeatable pipeline and explicit status semantics. The current private CRM must remain the source of truth. There is no public live interface yet, and this page deliberately omits response or placement metrics that would require a separate verified public snapshot.
